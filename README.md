# Lab3_Sem3 — лабораторная работа №3

Реализация структур данных на C++17 и Go. В C++ используются классы, наследование,
полиморфизм, композиция и управление ресурсами через конструкторы и деструкторы.
Версия Go находится в отдельной папке [`go`](go/).

## Структуры данных

| Класс C++ | Реализация |
| --- | --- |
| `Array` | Динамический массив строк |
| `FList` | Односвязный список |
| `LList` | Двусвязный список |
| `Stack` | Стек на основе `FList`, порядок LIFO |
| `Queue1` | Очередь на основе `FList`, порядок FIFO |
| `Tree` | Красно-чёрное дерево целых чисел |
| `HashTable` | Хеш-таблица пар ключ–значение с методом цепочек |
| `CuckooTable` | Кукушкина таблица ключей: два массива по 11 ячеек |

Контейнеры наследуют абстрактный класс `Serializable` с методами `Save` и `Load`.
Хеш-функции вынесены в отдельную иерархию `HashFunction`: `PolynomialHash`,
`CuckooHash1` и `CuckooHash2`. Таблицы используют их через `unique_ptr` — паттерн
«Стратегия». Стек и очередь предоставляют свой интерфейс поверх списка —
объектный «Адаптер». Метод `Clone` создаёт независимую копию хеш-стратегии.

## Требования для C++

- Компилятор `clang++` с поддержкой C++17 и `make`.
- Google Test и `pkg-config` для сборки тестов.
- `gcovr` и совместимый обработчик gcov для отчёта покрытия.
- `clang-format` для форматирования и `cppcheck` для статического анализа.

На macOS Makefile использует `xcrun llvm-cov gcov`, на остальных системах — `gcov`.
При смене компилятора нужно использовать совместимый с ним обработчик покрытия.

## Сборка и запуск C++

Все следующие команды выполняются из корня проекта:

```bash
make
./build/app --help
```

Формат запуска:

```bash
./build/app --file имя_файла.bin --query 'команда аргументы'
```

Один файл хранит одну структуру. Сначала его нужно создать соответствующей
командой инициализации. Повторная инициализация очищает данные в этом файле.
Остальные команды загружают структуру, выполняют операцию и при изменении сохраняют
её. Команды просмотра не перезаписывают файл.

Индексы начинаются с нуля. Значения с пробелами заключаются в двойные кавычки
внутри запроса. Неизвестная команда или неверные аргументы приводят к сообщению
об ошибке и коду завершения `1`.

### Пример: стек

```bash
./build/app --file stack.bin --query 'SInitStack'
./build/app --file stack.bin --query 'SPush 10'
./build/app --file stack.bin --query 'SPush 20'
./build/app --file stack.bin --query 'STop'
./build/app --file stack.bin --query 'SPop'
./build/app --file stack.bin --query 'STop'
```

Первый вызов `STop` выведет `20`, второй — `10`.

### Пример: хеш-таблица с цепочками

```bash
./build/app --file hash.bin --query 'HInitTable 8'
./build/app --file hash.bin --query 'HInsert name "Евгений Науменко"'
./build/app --file hash.bin --query 'HGet name'
./build/app --file hash.bin --query 'HContains name'
./build/app --file hash.bin --query 'HDelete name'
```

### Команды для остальных структур

| Структура | Инициализация | Примеры операций |
| --- | --- | --- |
| Массив | `MInitArray 4` | `MAddEnd a`, `MAddIndex b 0`, `MGet 0`, `MPrint` |
| Односвязный список | `FInitList` | `FAddEnd a`, `FAddAfter 0 b`, `FPrint` |
| Двусвязный список | `LInitList` | `LAddFirst a`, `LAddEnd b`, `LPrint`, `LPrintBac` |
| Очередь | `Q1InitQueue` | `Q1Insert a`, `Q1Front`, `Q1Back`, `Q1Delete` |
| Дерево | `TInitTree` | `TAdd 10`, `TFind 10`, `TDelete 10`, `TPrint` |
| Кукушка | `CInitTable` | `CInsert a`, `CContains a`, `CDelete a`, `CPrint` |

Команды из таблицы передаются через `--query`. Полный список и порядок аргументов
доступны через `./build/app --help`. Например, у `FAddIndex` сначала указывается
значение, затем индекс, а у `FAddAfter` — сначала индекс, затем значение.

## Сохранение и копирование

C++ сохраняет данные в бинарном формате. При загрузке узлы и их связи создаются
заново; адреса памяти в файл не записываются. Повреждённые данные проверяются до
замены состояния контейнера. Ошибка загрузки сохраняет прежнее состояние объекта.
Бинарный формат не является переносимым форматом обмена между разными архитектурами.

Конструкторы копирования и операторы присваивания обеспечивают независимое
владение памятью. У стека копирование списка выполняется его членом `FList`.
Копия очереди дополнительно восстанавливает собственный указатель на хвост.
Хеш-стратегии копируются через `Clone`, но в файл не записываются. При загрузке
кукушкиной таблицы должны использоваться те же стратегии, что и при сохранении.

Файлы C++ и Go не взаимозаменяемы: Go использует текстовый JSON.

## Тесты

```bash
make test
```

Запускаются тесты Google Test и 11 проверок командной строки из Makefile.
В `tests` проверяются операции контейнеров, граничные случаи, независимость копий,
коллизии, балансировка дерева, бинарная сериализация, повреждённые файлы и команды.
Общие вспомогательные средства находятся в `tests/test_support.h` и `.cpp`.

## Бенчмарки

```bash
make bench
```

`benchmark.cpp` измеряет время через `std::chrono::steady_clock` в микросекундах.
Программа собирается с `-O2`, без инструментирования покрытия. Для основных
структур выполняется добавление 10 000 элементов; время включает создание
контейнера, а массив заранее получает нужную вместимость.

У кукушкиной таблицы всего 22 ячейки, поэтому для неё выполняются 10 000 отдельных
серий по три ключа с созданием и уничтожением таблицы. Это другая нагрузка,
поэтому её время нельзя напрямую сравнивать с заполнением остальных структур.
Каждый замер выполняется один раз и зависит от компьютера и текущей нагрузки.

## HTML-отчёт покрытия

```bash
make gcov_report
```

Также доступна равнозначная команда `make coverage`.

Makefile собирает отдельные версии программы, тестов и бенчмарка с
`-O0 -g --coverage`, удаляет старые счётчики `.gcda`, запускает Google Test,
CLI-проверки и бенчмарк. Затем `gcovr` создаёт стандартный HTML-отчёт:

- [`build/coverage_report/index.html`](build/coverage_report/index.html) — общий отчёт и ссылки на исходники;
- `build/coverage_report/summary.json` — сводная статистика JSON;
- `build/coverage_report/summary.csv` — статистика для проверки порога каждого файла.

В метрику входят `struct`, `ProcessCommand.cpp`, `main.cpp` и `benchmark.cpp`.
Тесты и сторонние библиотеки исключены. Покрытие учитывает все перечисленные
запуски, а не только Google Test.

Порог строк и функций — минимум 90% в целом и в каждом файле с исполняемым кодом.
Порог ветвей (`Branches`) не установлен. Если покрытие ниже установленного порога,
команда завершается с ошибкой. Отдельно проверить готовую CSV-статистику можно
командой `make check-coverage`.

## Стиль и статический анализ

```bash
make format
make format-check
make lint
```

`make format` применяет `clang-format` к C++-коду и тестам.
`make format-check` проверяет оформление без изменения файлов и возвращает ошибку
при нарушениях. Правила находятся в `.clang-format`.

`make lint` запускает `cppcheck` с `--enable=all`. Замечания выводятся в терминал;
режим принудительного ненулевого кода завершения из-за замечаний не включён.

## Версия Go

Нужен Go 1.23 или новее. Все команды этого раздела выполняются из папки `go`.

```bash
cd go
make build
./build/lab3go --file stack.json --query 'SInitStack'
./build/lab3go --file stack.json --query 'SPush 10'
./build/lab3go --file stack.json --query 'STop'
make test
make bench
make gcov_report
```

Команды совпадают с C++ по именам и порядку аргументов. Для тестов используются
`testing` и `testify`, для анализа — `go vet`, для оформления — `gofmt`.
В Go цель `gcov_report` использует стандартное покрытие Go и создаёт
`go/build/coverage.html` относительно корня проекта.
